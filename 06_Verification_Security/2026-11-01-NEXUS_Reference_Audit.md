# AHMED AGENT / NEXUS ONE
## الوثيقة المرجعية الشاملة والمدققة — حصيلة 1 نوفمبر 2026

**الإصدار:** 1.0 — لقطة مرجعية قابلة للتثبيت  
**نطاق المراجعة:** Ahmed Core + NEXUS Gateway + Hermes + n8n Cloud + تطبيق iPhone + أمان التنفيذ + تشغيل Mac + قابلية النقل إلى Mac mini.  
**وضعها:** مرجع تقني متحقق من ملفات ومستندات منشورة؛ **ليس** شهادة جاهزية إنتاجية ولا تصريحًا بتعديل المشروع.  
**قرار التجميد:** إعداد هذه الوثيقة استثناء صريح من تجميد كتابة الوثائق؛ يظل الكود، الفروع، الأتمتات، مفاتيح الحسابات وإعدادات الإنتاج دون تغيير.

# 1. الحكم التنفيذي النهائي

**النتيجة المركزية:** لدى المشروع أجزاء حقيقية قابلة للاستفادة منها، لكنه لا يملك بعد دورة تشغيل مثبتة من «طلب على iPhone → تسجيل المهمة → عقل ينفّذ بحثًا وأدوات مخوّلة → تقرير موثّق محفوظ → حالة وإشعار على iPhone → استعادة من انقطاع». لذلك لا يصح إعلان نجاح 8/8 أو جاهزية منظومة وكلاء تعمل باستقلالية. [G01–G22]

**الوجهة العملية المتفق عليها:** البدء بالماك الحالي والآيفون وحساب Apple Developer المذكور من المستخدم؛ إبقاء Mac mini ترقية مستقبلية لا شرطًا مسبقًا؛ عدم جعل العالم السينمائي أو GPU أو إعادة كتابة التطبيق من الصفر حائلًا دون التشغيل. نواة مهام واحدة تتحكم بالسياسات والذاكرة والحالة؛ محرك تنفيذ قابل للاستبدال؛ أدوات ومهارات جاهزة موصولة بتصاريح محددة؛ n8n للعمليات الجاهزة لا بوصفه سلطة مطلقة على ملفات المستخدم.

**ثلاث حقائق لا تختلط:** (أ) الملف البرمجي موجود؛ (ب) الاختبار المحلي نجح؛ (ج) التشغيل الحقيقي على الماك والآيفون وn8n Cloud نجح. هذه مستويات أدلة مختلفة. لم يُجرَ في هذه المراجعة تشغيل على الأجهزة، ولا فحص صلاحيات حساب n8n Cloud، ولا تعديل على GitHub. نجاح CI في PR #7 لا يثبت (ج).

**أول نقطة استئناف معتمدة:** فحص الماك الحقيقي بأوامر قراءة فقط، ثم فرع تكامل جديد من main بعد حفظ بصمات المصدر، ونقل الاعتمادات والاختبارات الضرورية وتشغيل TypeScript والاختبارات، دون المساس بـmain. لا ضبط launchd أو تغيير النسخ أو إضافة أي أسرار قبل معرفة البيئة.

# 2. ماذا تعني «وثيقة مثبتة ومدققة»؟

نستخدم طبقات الدليل الآتية لتجنب التضخيم:

- **مؤكد من كود GitHub [G]:** رأينا ملفات ومسارات وتواقيع أو تعليمات تشغيل أو اختبار مكتوبة في فرع محدد وبصمة محددة. هذا دليل وجود كود، وليس دليل تشغيله على الماك.
- **مؤكد من توثيق رسمي [D]:** آلية مدعومة ومشروطة بالإصدار والحساب والإعداد المناسب؛ توثيق الشركات لا يعني أن الميزة فعالة في الحساب الشخصي.
- **قرار المستخدم [U]:** ما قاله المستخدم في المحادثة عن الهدف والأجهزة والتجميد. القرارات المعمارية الملزمة للتنفيذ تظل محدودة بنطاق موافقته ولا تعني إذنًا بالكتابة أو الإنفاق أو التفعيل.
- **توصية هندسية [R]:** تصميم مناسب لا يزال يحتاج اختبارًا وتثبيتًا فعليًا، مثل طبقة واحدة لحالة المهام أو معيار نقل Mac mini.
- **غير متحقق [X]:** وجود جهاز مناسب، نجاح Hermes محليًا، رقم إصدار n8n Cloud الفعلي، صحة مفاتيح API، وصول iPhone للنواة، تنفيذ قالب بحث حي، إشعارات، سجلات وأسرار وحسابات الجهاز.

**نطاق تدقيق هذا الإصدار:** مراجعة محتوى ملفات GitHub التالية عبر الموصل، مقارنة فروعها وتحقق جزئي من CI، ومراجعة توثيق الشركات الرسمي في قسم المصادر. لم تُراجع كل سطر في كل مستودع أو كل إعداد في الحسابات الخارجية؛ لا يوصف التدقيق بأنه تحليل اختراق كامل أو إثبات خلو من الثغرات.

**تصحيح بالغ الأهمية:** ليس صحيحًا أن المشروع يملك جدول مهام واحدًا جاهزًا؛ `main` يملك جدول `tasks`، بينما NEXUS يملك `nexus_missions`. المقصود بعدم إنشاء جداول موازية هو **ألا نضيف ثالثًا**، وأن نحدد مصدر حقيقة واحدًا للهاتف ولمسارات التشغيل مع خطة هجرة بيانات واختبار توافق؛ لا نحذف أي جدول قائم قبل تسوية اعتماده.

# 5. المعمارية الدنيا المرجعية — بعيدًا عن المظاهر

التسلسل المنطقي المقصود:

`iPhone Ahmed Agent → اتصال خاص + هوية جهاز → واجهة Core موحدة → دفتر المهام/الحوكمة/الميزانية → محرك واحد → أدوات مقيدة (بحث عام، ملفات مساحة العمل، n8n محدود، MCP مقيد) → سجل أحداث + تقرير ومراجع → حالة وإشعار iPhone`.

المكونات التي **تملك القرار** هي هوية المالك والجهاز، مدير المهمة، حارس الأدوات وAction Broker. النموذج اللغوي يفسّر ويخطّط، لكنه لا يصدر صلاحية ذاتية، ولا يرى مفاتيح الخدمات الحساسة. محرك Hermes إن استُخدم لاحقًا يكون عاملًا منفذًا خلف حدود النواة، لا منفذًا حرًا بصلاحيات الجهاز.

**فصل العمليات عن الواجهة:** تطبيق الآيفون لا يحمل API keys للنماذج، ولا رموزًا طويلة الأجل موضوعة في متغيرات `EXPO_PUBLIC_*`، ولا يحتاج إعادة بناء عند انتقال خدمة الماك إذا كانت هوية الخدمة وعنوانها قابلين للتبديل بإجراء اقتران آمن.

**الفصل بين مساري العمل:** بحث عام وإنشاء تقرير محلي مسموح فقط بعد تحقق حقيقي من حدود الأدوات والتكلفة؛ نقل أو حذف ملفات خاصة أو إرسال بريد أو تعديل Drive أو نشر مستندات يتطلب Action Broker مستقلًا وموافقة على فعل محدد.

| P1-10 | بناء تطبيق مستقل لحساب Apple Developer | `ios.bundleIdentifier`, `eas.json`, Development Build واختبار الجهاز؛ الحساب مذكور من المستخدم ولم يُفحص [G09,D08] |
| P1-11 | قياسات/سجلات وتشخيص ومسار إلغاء | معرفات correlation، قياس الوقت/التكلفة، إعادة اتصال، stop مؤكّد أو UNKNOWN، تنبيهات الفشل |
| P1-12 | جدولة/متابعة مهام في الخلفية | وجود دفتر مهام لا يعني Scheduler دائمًا؛ لا نعيد تشغيل أتمتات موقوفة بلا طلب صريح |

**P2 المؤجل:** واجهة سينمائية، تعدد وكلاء متقدم، RAG دلالي واسع، نماذج محلية ثقيلة، GPU، بيئة Mac mini الجديدة، الإضافات غير الضرورية لأول مهمة. التأجيل ليس إلغاءً للرؤية.

# 9. أربع قواعد تنفيذ مُثبّتة من نقاش اليوم

1. **الاعتماد على فرع كامل لا مجلد منعزل:** إنشاء فرع تكامل نظيف من `main` ونقل مكونات `nexus` و`services` والاختبارات والاعتمادات وملفات التهيئة الضرورية بصورة مراجعة؛ ثم TypeScript واختبارات قبل تغيير منطق التنفيذ. لا دمج شامل أعمى لـPR #7.
2. **مطابقة `Engine` الأصلية:** أي Adapter يعلن عن قدرات المحرك وينفذ الدوال السبع القائمة: `capabilities`, `start`, `status`, `stop`, `steer`, `approval`, `events`. لا نضيف واجهة موازية تختلف عنها من دون قرار صريح.
3. **الحراسة داخل مسار التنفيذ:** منع `move_file` وباقي الأدوات المجهولة/المحظورة داخل الدالة التي تملك الفعل والاعتماد، لا فقط في بداية المهمة، ولا بمجرد Prompt أو UI أو متغير بيئة.
4. **لا مسارات تشغيل افتراضية:** لا ملف launchd، ولا `/usr/local/bin/node` مفترض، ولا `dist/main.js` غير مبني، ولا إصلاح macOS قبل مخرجات فحص الجهاز الحقيقي.

هذه القواعد تثبت اتجاه العمل فقط. لا يترتب عليها إذن تلقائي بتعديل GitHub أو استيراد Workflow أو تمكين Scheduled triggers أو تمرير Credentials إلى نموذج.

# 10. العقود البرمجية الصحيحة المستخرجة من المصدر

**عقد NEXUS Execution (بصيغته الفعلية):**

```typescript
// nexus/server.ts - existing interface, not newly proposed code
authorizeExecution?: (
  mission: MissionRecord,
  config: NexusConfig
) => Promise<{
  allowed: boolean;
  maxCostMicroUsd: number;
  evidence: string;
}>;
```

- `evidence` **نص** وليس كائنًا. وجود النص لا يثبت أن الحارس يمنع أدوات Hermes تلقائيًا؛ يعتمد الأمان على Sandbox وحراسة الأدوات والتحقق من سقف المزود الفعلي.
- في النسخة الموجودة، `nexus/main.ts` لا يمرّر `authorizeExecution`؛ أما `/nexus/v1/missions` فيرفض المهمة بـ`EXECUTION_POLICY_UNVERIFIED` عند غيابها. [G10,G11]
- كود اقتراح سابق افترض `requestedCapabilities` اختيارية؛ اعتماد مصفوفة فارغة كدليل «صلاحيات آمنة» خطأ. القرار يجب أن يفحص **القدرات الفعلية** للوكيل والتوصيلات المسجلة، لا فقط ما صرح به العميل.

**عقد Engine داخل المستودع:**

```typescript
interface Engine {
  capabilities(): Promise<EngineCapabilities>;
  start(input: { input: string; instructions: string; model?: string },
        idempotencyKey: string): Promise<RunState>;
  status(runId: string): Promise<RunState>;
  stop(runId: string): Promise<RunState>;
  steer(runId: string, input: string): Promise<unknown>;
  approval(runId: string, requestId: string,
           choice: 'once' | 'deny'): Promise<unknown>;
  events(runId: string, after: number, signal: AbortSignal):
    AsyncIterable<{id: string | null; data: Record<string,unknown>}>;
}
```

هذا وصف الكود المفحوص، **وليس إقرارًا بتطابقه مع أحدث Hermes**. الوثائق الرسمية تضيف معرّفات دقيقة لجيل الموافقة `execution_generation` في بعض أوضاع التحكم، وتوضح مدة الاحتفاظ بمفاتيح Idempotency في Runs API؛ لذلك يلزم اختبار العقد حيًا عند نسخة Hermes الفعلية. [G13,D06]

# 11. n8n Cloud — مسار بحث غير متزامن وصادق

**المعلومة الرسمية المتحققة:** n8n Cloud خلف Cloudflare قد يعيد `524` إذا تأخرت استجابة Webhook عن 100 ثانية. توصي الوثائق بفصل بدء العمل عن الاستعلام عن الحالة/النتيجة. [D01]

**ملاحظة تصحيحية:** اختيار `Respond Immediately` يرجع افتراضيًا رسالة بدء تشغيل Workflow، **لا** يضمن JSON يحوي `$execution.id` أو HTTP 202. `$execution.id` متغير رسمي داخل تنفيذ n8n، لكن إرساله للنواة يحتاج عقد استجابة مخصصًا أو حفظًا داخليًا وربطًا بالمهمة. [D02,D03]

العقد المطلوب تصميمه واختباره، وليس كودًا منفذًا اليوم:

- **طلب البدء:** مدخلات محصورة `missionId`, `requestId`, `query`, `policyVersion` ومصادقة موثوقة. النواة وحدها تختار Workflow المسموح؛ العميل لا يرسل URL خارجيًا حرًا.
- **الرد السريع:** تأكيد قبول التنفيذ وهوية قابلة للتتبع؛ قد يكون `executionId` الرسمي أو مرجع job محليًا عند النواة، لكن يجب إثبات طريقة استخراجه. لا نعرض 202 إلا إذا أرسلناها فعليًا.
- **حالة ممتدة:** `queued → running → completed / failed / unknown` مع تطابق `missionId` و`requestId`، وتحميل النتائج عند اكتمالها عبر API موثوق أو Callback بتوقيع ومدة وصلاحية محددة.
- **الفشل والانقطاع:** عدم إعادة إرسال طلب بدء لمجرد انقطاع HTTP؛ تسوية حالة التنفيذ بواسطة معرّف محفوظ، مع حد للمحاولات ورسالة صريحة عندما لا يمكن معرفة النتيجة.
- **فحص المراجع:** فحص HTTP من خلال طبقة SSRF موحدة؛ تسجيل النتيجة الفعلية، مع مقارنة الاقتباس/المعلومة بمحتوى المصدر، وإشارات عندما تبقى الدعاوى غير مؤكدة.
- **أمان Cloud:** منع وصول أسرار الجهاز أو ملفات PRIVATE_VAULT إلى Workflow إلا بعد منح محدد؛ جرد Credentials الحالية والتدفقات المفعلة وTriggers/Scopes قبل التشغيل.

**القالب الجاهز موضع الدراسة:** `Open deep research - AI-powered autonomous research workflow` يستخدم SerpAPI وJina AI وOpenRouter؛ وجوده في مكتبة n8n **لا يعني** أنه موجود أو مفعل في حساب المستخدم أو أنه يلتزم تلقائيًا بسياساتنا. [D14]

**تحديث n8n:** واجهة Cloud Console شهدت تغييرات في أكتوبر 2026؛ مسار الإعدادات يتغير بحسب شكل الواجهة والصلاحية. لا نشترط نسخة مفترضة مثل `>2.42.1` ولا نحدث الحساب قبل معرفة نسخته، تقييم تغييرات الإصدار، التوقيت وتأثير التوقف. [D04,D05]

# 12. Hermes — محلّه الصحيح وحدود الثقة

واجهة `HermesClient` في الفرع موصولة محليًا إلى origin من نوع loopback فقط مع مفتاح API. هذا يحدّ من الاتصال بهذا الموصل، لكنه **لا يقيد تلقائيًا الأدوات والملفات والشبكة التي يملكها خادم Hermes نفسه**. [G13]

وثائق Hermes الرسمية تثبت وجود Runs API و`GET /v1/capabilities` و`POST /v1/runs` وبث SSE والإيقاف والموافقات، وتذكر إمكانية كشف المهارات والأدوات عبر endpoints خاصة. لكنها لا تثبت توفر كل ميزة في إصدار جهاز المستخدم؛ تُفحص `capabilities()` والتواقيع عند الاختبار. [D06]

**حد نواة Hermes الآمن المطلوب:** تشغيله كعامل محدود الأدوات/الامتيازات/الأسرار، تعريض APIs المطلوبة فقط خلف Gateway، منع ممر جانبي إلى نظام الملفات أو الخدمات الخارجية، وحصر تكلفة النموذج والبحث. الموافقة التي تعيدها واجهة Hermes ليست بديلًا عن Action Broker عند الفعل الحساس.

**عند توفر Mac mini لاحقًا:** غالبًا يكون Apple Silicon، لكننا لا نفترض مواصفات شراء لم تُحسم بعد؛ نجري اختبار نسخة التثبيت والدعم عند وصول الجهاز. [D07]

# 13. الأمان الفعلي — ليس مجرد قوائم سماح

**13.1 الهوية:** `EXPO_PUBLIC_APP_TOKEN` منشور داخل حزمة Expo ولا يجوز اعتباره سرًا. نحتاج اقتران مالك وجهاز بإثبات امتلاك مفتاح، ونطاق صلاحية لكل محادثة ومهمة، وتدوير/إبطال وتسجيل. معرّف نصي مثل `deviceId` لا يثبت هوية جهاز. [G07,G19]

**13.2 موافقات الأفعال الحساسة:** PR #7 يحتوي هيكل Action Broker مع P-256 ECDSA وnonce ومدة، وتخزين حجز ذري وحالة UNKNOWN بعد فشل لاحق. هذه وحدة **مرجعية غير مدمجة** في المسار الحي. اعتماد توقيع صحيح لا يثبت وحده أن المفتاح أنشئ داخل Secure Enclave؛ يلزم اختبار جهاز وسياسة enrollment وربما attestation مناسبة. [G20,G22]

**13.3 تطابق الصيغة:** PR #7 يستخدم حقول ActionEnvelope بأسلوب `camelCase`، بينما مقترحات العقد v1.3 نوقشت فيها `snake_case`. لا يجوز الخلط أو توقيع JSON مختلف بين iOS وNode؛ تُعتمد صيغة canonical واحدة ومتجهات اختبار طرفية مع RFC 8785 عند التنفيذ، ولا نعلن حسم التعارض الآن. [G20,G22]

**13.4 سرّية الأدوات والموصلات:** منفذ الأفعال الحساسة يجب أن يعمل بصلاحيات وSecrets منفصلة عن النموذج والعمال. تصنيف المخاطر ليس ضمانًا؛ أدوات مجهولة تُحظر. لا تنشئ رخصة عامة للأدوات بسبب `readOnlyHint` أو اسم أو وصف يوفره خادم MCP. [G22]

**13.5 تصنيف البيانات:** PUBLIC_WEB / WORKSPACE_LOCAL / PRIVATE_VAULT. القراءة المحلية لا تعني السماح بالإرسال إلى نموذج أو n8n Cloud؛ أي egress لملف خاص يحتاج سياسة صريحة، ولـPRIVATE_VAULT موافقة خاصة على المحتوى والجهة والهدف. مدخلات ويب/ملفات خارجية غير موثوقة وتُعامل كبيانات لا تعليمات.

**13.6 القصور الإنتاجي المتعمد:** الفرع الأمني يضبط `remoteN8nVerified` على false ويمنع وضع production. لا نغير الثابت إلى true شكليًا ولا نعطل الحاجز لإظهار نجاح زائف. [G19,G21,G22]

**13.7 أمان HTTP:** `publicHttpGet` الجاهز يحمي من فئات SSRF في هذه الدالة وحدها، لكنه لا يغطي `fetch` المباشر في موصلات أخرى تلقائيًا. عند البناء يُستخدم مسار خروج موحد يراجع URL وIP والتحويلات وحدود الاستجابة ومصدر البيانات. [G17]

# 14. الذاكرة والمعرفة والملفات

منفصلان اليوم: `MemoryService` يحتفظ برسائل الجلسات ويبحث نصيًا، و`KnowledgeVault` يقرأ ملفات مساحة العمل، يتحقق من SHA-256، يبني مقاطع نصية مع ACL لكل وكيل ويسترجع بواسطة `LIKE`. هذا تأسيس مفيد، لكنه لا يمنح استرجاعًا دلاليًا موثوقًا أو حماية تلقائية من إدراج نصوص خبيثة في نتائج البحث. [G15,G16]

المطلوب في أول مهمة هو **ذاكرة تشغيلية** قبل القفز إلى RAG متقدم: تخزين معرف المهمة، طلب المستخدم، حالة التنفيذ، مصادر البحث، البصمات، تقرير النتيجة، إشعار التسليم وحالة الفشل. لا نخلط رسالة نموذج مع حالة تنفيذ موثقة.

**الملفات:** قارئ main يدعم `.txt`, `.md`, `.pdf` النصي ويدعم حدًا أقصى للحروف. الصور وصفحات PDF المصورة وOCR ليست قدرات مثبتة. تقرير Markdown الناتج يُحفظ في مسار فرعي معزول باسم يولده الخادم، بلا الكتابة فوق ملف قائم؛ الفحص `path.basename` وحده لا يثبت سلامة symlink أو TOCTOU. [G04,G15]

**مصداقية المراجع:** `HTTP 200` لا يعني أن الفقرة نقلت المعنى الصحيح. تقرير المهمة يجب أن يفصل: (1) رابط يجيب؛ (2) نص أو دليل استُخرج؛ (3) علاقة الادعاء بالدليل؛ (4) درجة الثقة/التحفظ؛ (5) تاريخ الوصول وملكية المصدر. مهارة `grounded-citations` موجودة رسميًا في Hermes، لكنها تحتاج تركيبًا وتشغيلًا وتقييمًا في مشروعنا، لا مجرد ذكر اسمها. [D13]

# 15. تشغيل الماك الحالي — شروط القراءة قبل التغيير

لا نعرف من هذه المحادثة مخرجات Terminal الحالية، ولا نفترض Intel أو Apple Silicon بعد احتمال تبديل الجهاز. أمر الفحص التالي **قراءة فقط** ويعطي بيانات لا تكشف أسرارًا:

```bash
sw_vers -productVersion
uname -m
node -v
command -v node
git --version
command -v docker
command -v tailscale
df -h / | tail -1
sysctl -n hw.memsize
```

قد يظهر `command not found`؛ لا يتوقف الفحص عندها لأن الأوامر سطور مستقلة. يحتاج Expo SDK 57 في المشروع إلى Node.js 22.13.x كحد أدنى وفق توثيق Expo؛ وهذا **لا** يضمن أن جميع الاعتمادات تعمل على كل إصدار macOS قديم. [G09,D08]

**خطة التشغيل بعد الفحص:** مراجعة البيئة أولًا؛ تنفيذ `npm ci`, TypeScript tests على فرع التكامل؛ اختبار استجابة النواة محليًا؛ ثم خدمة `launchd` بمسار Node وWorkingDirectory حقيقيين ومجلد سجلات موجود. المشروع اليوم يستخدم `tsx src/main.ts` في scripts، ولا يضمن ملف `dist/main.js`. إعداد `NODE_ENV=production` في فرع PR #7 يفعل الحاجز المذكور؛ لا نعالجه بتغيير شعار أو تجاوز. [G01,G19]

**الشبكة:** نواة Ahmed الأساسية تستمع افتراضيًا إلى `0.0.0.0:8787`، وNEXUS إلى `127.0.0.1:8788`. يجب توحيد عنوان الوصول أو وضع Proxy خاص، وعدم إعلان المنفذين للعامة. Tailscale Serve يتيح نشر خدمة محلية داخل tailnet مع ضوابط وصول، ولا يحل مصادقة التطبيق بمفرده. [G01,G10,D11]

**الاستمرارية:** `launchd` يعيد تشغيل العملية عند تعطلها لكنه لا يحل المنطق المهني للمهام، ولا يضمن استيقاظ الماك أو الاستعادة بعد إغلاق الجهاز. النسخ الاحتياطي يجب أن يكون SQLite-safe (بما في ذلك WAL) مع اختبار استعادة فعلي؛ لا يكفي نسخ ملف قاعدة البيانات أثناء الكتابة بشكل غير منضبط.

# 16. تجهيز iPhone من دون إنشاء تطبيق جديد

**الموجود:** `App.tsx` محادثات ومهام وموافقات واستطلاع؛ `api.ts` عنوان Core مثبت بمتغير `EXPO_PUBLIC_CORE_URL` وتوكن منشور في حزمة التطبيق. `app.json` لا يثبت اكتمال معرّف bundle أو EAS وتوقيع iOS. [G07,G08,G09]

**المطلوب لنسخة iPhone Development Build:** إدخال `ios.bundleIdentifier` فريد، ملف `eas.json`، `expo-dev-client` عند الحاجة، ربط Apple Developer وExpo/EAS، تسجيل جهاز وتجربة البناء؛ ثم مصادقة جهاز متحقق منها وسجل اقتران قابل للإبطال، وعنوان Gateway آمن قابل للتبديل. خدمة EAS تبني iOS عن بعد، فلا يشترط شراء Mac mini لبناء نسخة تطوير عبر السحابة. [D08,D09]

**الإشعارات:** `expo-notifications` ليست إضافة تُغلق الموضوع بمجرد استدعاء `getExpoPushTokenAsync()`؛ تتطلب إعدادًا للتطبيق وCredentials APNs/إذن المستخدم ومزوّد إرسال وربط PushToken بحساب وجهاز واختبار تسليم ومتابعة الفشل. لا نعتبر رمز Push وسيلة إثبات هوية. [D10]

**الصوت المباشر:** ميزة مستقبلية مهمة للهدف الشخصي، لكنها ليست من شروط أول مهمة بحث نصية موثقة. مصدرها ومكالماتها وصلاحياتها وكلفتها يُختبر في Development Build حقيقي، لا Expo Go فقط.

# 17. انتقال من الماك الحالي إلى Mac mini لاحقًا

لا نبني منظومتين؛ تتغير آلة الاستضافة فحسب عند جاهزية Mac mini. الأصول التي يجب فصلها عن الجهاز: قاعدة مهام SQLite ونسخة backup متسقة، مجلد ملفات مساحة العمل والتقارير وبصماتها، إعدادات نسخة الكود، ملفات سياسة المستخدم والتكاملات، وعناوين الخدمات والقنوات التي تحتاج إعادة اقتران أو تدوير Secrets لها.

**اختبار النقل قبل القطع:** إصدار Backup، تحقق من سلامة الملفات والأحداث، تشغيل نسخة معزولة على الجهاز الجديد، إعادة توجيه Tailscale Serve/هوية Gateway بطريقة مضبوطة، إيقاف العامل القديم لتجنب **تشغيلين متزامنين للمهمة نفسها**، اختبار اشتراك iPhone واسترجاع تقرير محفوظ، وبعدها فقط تحويل الخدمة الرئيسية. لا تنقل أسرارًا في Git أو داخل التطبيق.

# 20. اختبارات إضافية إلزامية قبل استخدام بيانات حقيقية

- **أمان API:** رفض token عام قديم، رفض جهاز ملغى، فصل محادثات، طلب معرف مكرر بمدخل مختلف = 409، عبث بالتوقيع والمعلمات = deny.
- **أمان أدوات:** رفض unknown tool؛ رفض `move_file` في وضع القراءة حتى عبر مسار الموافقة القديم؛ رفض `tools/call` غير موصول؛ منع `n8n` من استدعاء أفعال حساسة.
- **شبكة وخروج:** URLs من نوع localhost/metadata/IPv6 خاصة، إعادة توجيه DNS/SSRF، ملف خاص يُحقن في سؤال بحث سحابي، مصدر ويب يطلب «تجاهل التعليمات».
- **حالة/تكرار:** انقطاع قبل/بعد رد 202، انقطاع بعد تنفيذ خارجي وقبل إيصال مؤكد، callback مكرر/متأخر/مزوّر، stop مع مهمة ما زالت جارية، إعادة تشغيل الماك أثناء Polling.
- **قاعدة البيانات:** اختبار SQLite WAL/backup، الاسترجاع من نسخة سليمة، تضارب تدوين حالة، عدم ضياع مصدر التقرير/بصمته.
- **المصادر:** صفحات 200 بلا سند، 403/404/HEAD لا يدعم، التحقق من المقطع الداعم، تاريخ المصدر، تقرير بلا مراجع مع بيان فشل صريح.
- **iPhone:** شبكة Wi-Fi ثم بيانات الهاتف، انتهاء Tailscale session، إلغاء التثبيت وإعادة الاقتران، فشل APNs، إلغاء الهوية، تغيير عنوان Mac mini.
- **التكلفة/القابلية للتشخيص:** ميزانية عامة وفردية، حجز مقابل صرف مزود فعلي، timeout، مراقبة الأخطاء، إيقاف تفعيل Scheduled workflows غير المصرح بها.

# 21. التصحيحات الحاسمة للشيفرات المقترحة في النقاش

# 22. سجل القرارات ونطاق الموافقة

**معتمد كاتجاه عمل من المحادثة:** Mac الحالي وiPhone أولًا؛ حساب مطور Apple متاح بحسب تصريح المستخدم؛ Mac mini لاحقًا؛ إعادة استخدام Ahmed Agent؛ عدم بناء عالم سينمائي شرطًا أساسيًا؛ منع التكرار؛ اختيار مسارات وأدوات جاهزة؛ قاعدة منع كتابة كود أو إعدادات متعلقة بالجهاز قبل فحصه؛ تجميد عمليات المشروع والأتمتات حتى قرار تشغيل صريح؛ تنفيذ خطوة واحدة ثم اختبارها.

**مقترحات هندسية تحتاج قبولًا عمليًا واختبارات:** أي توزيع فعلي بين Hermes/Ahmed Core/n8n؛ آلية اقتران iPhone؛ اختيار مزود بحث ورسومه؛ صيغة envelope النهائية؛ صلاحيات Cloud؛ مسارات إخراج الملفات والنسخ؛ سياسة privacy tiers؛ التعافي من التشغيل الغامض؛ شروط تمكين صوت مباشر.

**لا يُفهم من إعداد هذه الوثيقة:** تصريح بتفعيل Cron، دمج PR، تغيير DNS أو حساب Apple، إنشاء Workflow في n8n، تعديل secrets، مشاركة محتوى خاص في السحابة، تنفيذ عمليات دفع/رسائل خارجية، أو حذف/تدوير credentials.

# 23. ما الذي لا نعرفه بعد ولن نخمنه؟

1. نوع الماك الحالي فعلًا، إصدار macOS وNode وGit، سعة التخزين الحرة والذاكرة، وتثبيت Tailscale/Docker.
2. ما إذا كانت الملفات في جهاز الماك مطابقة لرأس GitHub أو تحوي تغييرات محلية غير مدفوعة.
3. تشغيل Hermes/API Server فعليًا أو نسخته في الجهاز؛ صلاحياته وأدواته وشكل جيل الموافقات الحالي.
4. إصدار n8n Cloud الفعلي، قائمة Workflows المنشورة، Credentials، Webhooks، Trigger schedules، صلاحيات MCP، وتكلفة وأمان المنصة.
5. صلاحية ربط Apple Developer/EAS، معرّف Bundle، نجاح توقيع Development Build، نجاح Secure Enclave/Push على iPhone حقيقي.
6. مزود النموذج وAPI keys الصالحة، حدود الفوترة، سياسة الاحتفاظ بالمحتوى والمعلومات الحساسة.
7. سلامة اختبار بناء أحدث نسخة على بيئة الماك، وعدد tests الناجحة **على الفرع الموحد**؛ الأرقام المتداولة مثل «53 اختبارًا» ليست بديلًا عن مخرجات تشغيل لهذا الفرع.
8. ما إذا كان من الضروري نقل بيانات قديمة أو محادثات سابقة إلى معمارية موحدة، وحجمها الحقيقي.
