# المنظومة | مشروع تطبيق iPhone أصلي مع Core خاص (v0.1)

**المحتوى حقيقي وقابل للتعديل، وليس مجرد صور للواجهة.** يشمل مجلد `iOS` مشروع Xcode بـ SwiftUI، ومجلد `Core` خادم Node.js مع SQLite وذاكرة وسجل مهام واقتران جهاز وتوقيع الموافقات. في مجلد `Preview` تجد صور تصميم توضيحية ونسخة HTML استعراضية **لا تمثل لقطات من التطبيق المبني على هاتف**.

## البداية السريعة

1. على Mac مزود بـXcode وإصدار SDK يدعم iOS 26، افتح `iOS/AlManzoma.xcodeproj`. اختر فريق Apple Developer الخاص بك من Signing & Capabilities؛ عدّل Bundle Identifier إن لزم. اختر iPhone الحقيقي وجرّب Build/Run.
2. على Mac نفسه أو خادم خاص، شغّل Node.js **22.13 أو أحدث**. `cd Core && npm test` للتحقق، ثم شغّل موصل نموذج فعلي: مثلًا Ollama محليًا بعد تنزيل نموذج مناسب لمواصفات الجهاز، أو مزود API ببيانات اعتماد محفوظة **على Core فقط**.
3. داخل `Core` اضبط متغيرات البيئة كما في `.env.example` ثم شغّل `npm start`. بشكل افتراضي يستمع Core على `127.0.0.1:8787` ولا يُعرض مباشرة على الإنترنت العام. هذه المسودة **ليست خادمًا إنتاجيًا محصنًا**؛ لا تنشرها علنًا.
4. بعد تهيئة Tailscale على الهاتف والخادم، أعرض خدمة Core عبر HTTPS خاص (Tailscale Serve)، واستخدم عنوانها مثل `https://your-device.your-tailnet.ts.net` في إعدادات تطبيق الآيفون. لا تستخدم Funnel العام.
5. على جهاز Core نفّذ `npm run pair` للحصول على رمز تسجيل الجهاز المؤقت. ضعه في شاشة الإعدادات بالتطبيق؛ ينشئ التطبيق مفتاح توقيع في Secure Enclave ويثبت ملكيته عند Core. لا ترسل رمز الاقتران أو مفاتيح API لأي شخص أو نموذج.
6. بعد نجاح الاقتران وظهور أن النموذج متاح، اكتب أول رسالة. سترى الرسالة ونتيجتها في تاريخ المحادثة. إذا طلبت حفظ ملاحظة أو إنشاء مهمة، يعرض Core طلبًا لا ينفذ قبل اعتمادك بتوقيع الجهاز المحمي بالبيومترية.

> متغيرات البيئة في `.env.example` *لا تُقرأ تلقائيًا* من Node. اضبطها في جلسة الطرفية التي تشغّل منها الخادم أو باستخدام مدير أسرار. مثال محلي دون مفتاح خارجي: `CORE_PROVIDER=ollama CORE_MODEL=qwen3:4b npm start`، بعد التأكد من أن Ollama يعمل وأن النموذج المذكور متاح على جهازك.

## ما الذي تجده داخل الحزمة؟

- `iOS/AlManzoma.xcodeproj`: تطبيق SwiftUI مع Chat وSpaces وActivity وSettings والإملاء والقراءة الصوتية عبر واجهات النظام.
- `Core/src`: API لعناوين `health`, `spaces`, `conversations`, `messages`, `runs`, `proposals`, `activity`, `learning`, `memory/search`. SQLite بميزة WAL وFTS5، وطلبات idempotency، وتوقيع P-256 وقرار موافقة محمي.
- `Contracts/openapi.yaml`: توثيق أولي لعقد HTTP بين تطبيق iPhone وCore.
- `Preview/chat.png`, `activity.png`, `spaces.png`: صور *تصورية* للتصميم؛ و`index.html` عرض HTML منفصل لا يحل محل Xcode.
- `QA/`: نتائج الاختبارات البرمجية، وتقرير حدود التحقق.
- `Docs/`: تعليمات التشغيل والفروق بين المنفذ والناقص.

## أين الذكاء؟

يأتي الرد الذكي من **نموذج حقيقي تختاره أنت لتشغيله على Core** (Ollama محلي أو API خارجي). ليست هناك إجابات مزيفة أو نموذج مخبأ داخل تطبيق iPhone. الخادم يدير نص المحادثة، بحثًا ضمن الذاكرة، والبحث بالمصادر عند إعداد موصل Tavily؛ وتبقى قرارات الأدوات الفعلية خارج سيطرة النص الذي ينتجه النموذج.

## ما الذي لم يتحقق بعد؟

لم يتم بناء `.ipa`، ولم يُختبر المشروع داخل Xcode أو على iPhone، ولا يوجد نموذج ذكاء حقيقي أو مفاتيح API داخل الحزمة. نجحت اختبارات Core باستعمال **موصل نموذج اختبار يحاكي استجابة Ollama**؛ لم تثبت هذه الاختبارات جودة نموذج أو الاتصال بمزود إنتاجي. ليست هذه نسخة جاهزة للنشر أو للأوامر الخارجية الحساسة أو لإدارة صلاحيات واسعة؛ لا توجد نسخ احتياطية أو تصدير مشفر أو اختبارات شبكة/استعادة نهائية بعد.

**تنبيه أمني:** الاختبارات لا تمنح ضمان أمان أو نجاح إنتاجي. قبل استخدام بيانات حقيقية، راجع إدارة الأسرار، ونسخ SQLite الاحتياطية والاستعادة، وحدود الأسعار، وسياسة الحفاظ على البيانات، والتصديق الشبكي، وعمليات التحديث والتوقيع في Xcode.
